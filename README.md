# LOF 溢价率自动采集与看板

一个静态 LOF 溢价率监控页面。GitHub Actions 在工作日交易时段调用上游公开行情接口，每 30 分钟保存一次快照，并自动发布到 GitHub Pages。

页面包含：

- 当前基金溢价率排名、场内价格和场外估值
- 当日、最近 5/7/20/60 个交易日及全部历史走势（默认最近 7 个交易日）
- 顶部溢价率折线与日成交量柱图按交易日对齐，点击/悬停柱子可看成交量、成交额，也可展开逐日明细
- 三个估值数据源的昨日偏差与“昨日最准”结果
- 搜索、基金分类和正溢价筛选

## 数据保留

- 最近 60 个交易日保留每 30 分钟快照。
- 更早数据压缩为每个交易日最后一个快照。
- 逐日数据源准确度文件保留最近 60 个交易日。
- 浏览器按基金代码单独加载走势文件，不会一次下载全部历史。
- 日成交量首次补最近 60 个交易日范围，后续按日增量合并并持续保留；不复制到每个半小时快照。

## 日成交量：口径与采集

数据来自通达信沪深市场日 K，成交量单位为**基金份额（份）**，成交额单位为人民币元；页面统一换算为**万份 / 万元**，显示最多四位小数。新协议中的 volume 已经是份，不能再乘以 100。当日没有返回记录时显示缺失，不将其解释为零成交或停牌；真实零值会保留。上游使用 float32 编码，大成交量/额可能存在浮点精度误差。

pytdx 的 `get_security_bars(9, market, code, 0, count)` 在接口设计上包含 `vol` 与 `amount`，但 2026-10-05 对 1.72 的实测中，自带两个旧节点超时，当前主站连接成功后日 K 解析报 `unpack requires a buffer of 4 bytes`。因此本项目使用 `tdx_v2.py` 的当前 `00 0a` 协议，沿用量化项目的修复思路。该适配器来源及 MIT 许可见文件头和 `licenses/tdxrs-MIT.txt`。

工作流北京时间工作日 **16:10** 获取已收盘数据，**18:10** 补跑。日成交量步骤不在半小时溢价采集中执行；16:00 前的手动运行也会排除当天未完成的日 K。GitHub cron 按 UTC 配置且可能延迟。

- 先用 `510300` 真实日 K 验证三个节点，并以其返回日期构建交易日序列，不用普通工作日代替交易日。
- 最新基准日期不能早于已保存日期或已完成的溢价快照日期。某基金最新记录落后时会继续尝试其他健康节点，仍缺失则如实标记。
- 新基金自动回补历史；已有基金请求“距上次成功查询的天数 + 5”根日 K，按日期去重并修正重叠部分，可补回漏跑的多天。
- 当基准交易日和基金池都没有变化时，仅探测基准，不重新抓取全部基金、不改成交量文件、不产生数据提交。
- 全基金池通过日期、非负数、成交额/成交量与价格范围校验后才原子替换数据；任一基金完全取数失败则失败退出，保留旧快照。

手动采集、构建与测试（Python 3.9+，Node.js 18+；新增生产代码无第三方依赖）：

```bash
python3 collect_daily_volume.py
python3 build_dashboard_data.py
python3 -m unittest discover -s tests -v
node --test tests/chart.test.cjs
```

重抓近期历史用于修正：`python3 collect_daily_volume.py --refresh-history`。默认重抓 60 根，可用 `--backfill-days` 调整至 7–700；更老的已保存数据保留。中断超过 695 个自然日需要人工指定回补范围核查，脚本不会默默截断缺口。Actions 手动运行时可勾选 `collect_volume` 和 `refresh_volume_history`。

## 自动采集

工作流位于 `.github/workflows/collect-and-deploy.yml`，工作日北京时间按以下标准时点采集：

```text
09:30  10:00  10:30  11:00  11:30
13:00  13:30  14:00  14:30  15:00
```

GitHub 定时任务在标准时点后 5 分钟触发，以降低整点排队概率。周末、节假日或上游数据尚未更新到当天时，采集器会跳过写入。

手动运行：

```bash
./run_api_collection.sh --force
```

手动强制运行在交易时段之外时，会写入最近的标准采集时点，不会产生非交易时间快照。

## 文件结构

- `data/daily/YYYY-MM-DD.json`：最近交易日的盘中快照。
- `data/archive/YYYY.json`：超过保留期的每日收盘快照。
- `data/source_accuracy/`：数据源准确度记录。
- `data/latest.json`：最新快照。
- `data/volume/latest.json`：日成交量持久历史，`points` 每行依次为 `[交易日, 成交份额, 成交额元]`；`checked_through` 为已查询至的基准交易日，并非每只基金都有该日成交记录。
- `site/`：GitHub Pages 静态页面和构建后的网页数据。
